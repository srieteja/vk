Locate any LIKE queries in AdvocateService (likely in search or filter methods). Apply the SQL injection prevention pattern from research Pattern 1 (lines 83-145):

1. Find existing location search method (likely `SearchByLocation`, `FilterByLocation`, or similar)
2. If no dedicated method exists, create `SearchByLocation(ctx context.Context, location string)` method
3. Implement three-layer protection:

   **Layer 1: Validate input format**
   ```go
   filter := &validators.LocationFilter{Location: location}
   if err := validator.New().Struct(filter); err != nil {
       return nil, fmt.Errorf("invalid filter: %w", err)
   }
   ```

   **Layer 2: Escape wildcards**
   ```go
   safeLocation := validators.EscapeLikeWildcards(filter.Location)
   ```

   **Layer 3: Use parameterized query with ESCAPE clause**
   ```go
   var advocates []Advocate
   if err := s.db.Where(
       "LOWER(location) LIKE ? ESCAPE '\\'",
       "%"+strings.ToLower(safeLocation)+"%",
   ).Find(&advocates).Error; err != nil {
       return nil, err
   }
   ```

4. CRITICAL: The ESCAPE '\\' clause tells PostgreSQL/SQLite that backslash is the escape character, so escaped wildcards (\%, \_) are treated as literals.

5. Search for any other LIKE queries in the file (grep for "LIKE" pattern) and apply same escaping pattern.

DO NOT use string concatenation or fmt.Sprintf for building SQL - only GORM parameterized queries.
DO NOT use Raw() SQL - use Where() with placeholders.

Reference: Research Pattern 1, lines 116-137. Avoid anti-patterns from lines 148-158.
  </action>

3. Build service: `go build ./internal/services`
